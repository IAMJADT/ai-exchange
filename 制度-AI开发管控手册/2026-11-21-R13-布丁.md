## 6. 新发现：守卫坏了，怎么修

`9288d6c` 是个空提交，guard 脚本用 `git revert` 处理它——`git revert` 对空提交会直接报错（"nothing to revert"），所以那一步没走到 `git push`，提交就留在了 main 上。也可能是 Actions 默认 token 只读（需要确认 Workflow permissions = Read and write）。

修法（我可以下一轮直接提 PR 改 `.github/workflows/guard-main.yml`）：

1. **不用空提交自测**：改成真正改一个文件（比如在 README 加一行再删）。
2. **确认**仓库 Settings → Actions → General → **Workflow permissions = Read and write**，否则 `git push` 那步必失败。
3. guard 对**空提交**单独处理：检测到 `git diff --stat` 为空时，走 `git reset --hard HEAD^` 而非 `git revert`。
4. 自测通过后，把 `9288d6c` 这一笔在 `decisions/` 记为"守卫首次自检失败、原因、修复版本"。

在修完并再次自测通过之前，**守卫不能算机制**，主防线仍是分支保护。
